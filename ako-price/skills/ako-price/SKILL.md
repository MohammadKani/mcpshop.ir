# Ako Prices

اسکیل دریافت قیمت روز **دلار، طلا و سکه** از ، با خروجی ثابت و استاندارد:
یک جدول فارسی راست‌به‌چپ برای خواندن، و یک آبجکت JSON با کلیدهای انگلیسی برای
استفاده‌ی مجدد (داشبورد، بریفینگ روزانه، اسکریپت دیگه).

این اسکیل **کاملاً مستقل (standalone)** است — هیچ اسکریپت پایتون یا فایل
کمکی اجرا نمی‌شود. خودِ Claude باید استخراج، محاسبه‌ی رند کردن، و قالب‌بندی
را طبق قوانین دقیق زیر انجام دهد.

**هرگز** مجموعه‌ی موارد، قانون رند کردن، یا ساختار خروجی را خودسرانه تغییر
نده. اگر کاربر چیز دیگری خواست (موارد بیشتر، رند کردن متفاوت)، فقط برای همان
درخواست انجامش بده و قبل از تغییر دائمی این فایل، از کاربر بپرس.

## شش مورد الزامی (به همین ترتیب)

| title_fa (نوع) | key | نماد در baha24 | واحد خام |
|---|---|---|---|
| دلار | `usd` | USD | toman |
| انس طلا | `gold_ounce` | OUNCE | usd |
| گرم طلا | `gold_gram` | GOL18 | toman |
| سکه امامی | `coin_emami` | EMAMI1 | toman |
| نیم سکه | `coin_half` | AZADI1_2 | toman |
| ربع سکه | `coin_quarter` | AZADI1_4 | toman |

هر شش مورد معمولاً مستقیماً در صفحه‌ی اصلی baha24.com هست (نیازی به رفتن به
صفحه‌ی جزئیات هر مورد نیست)، مگر این‌که یک ردیف در صفحه‌ی اصلی پیدا نشود — در
آن صورت فقط برای همان مورد به لینک جزئیاتش برو (مثلاً
`https://baha24.com/price/قیمت_دلار`).

## روند کار

1. **دریافت صفحه**: با ابزار web fetch آدرس `https://baha24.com/` را بگیر.
   هرگز از قیمت‌های حافظه یا قبلی استفاده نکن — همیشه تازه بگیر.

2. **استخراج مقدار خام هر مورد**: برای هر ردیف بالا این‌ها را استخراج کن:
   - `raw_price`: عدد قیمت بدون کاما و بدون واحد (مثلاً «۱۸۱,۸۰۰ تومان» → `181800`)
   - `raw_currency`: `"toman"` برای ردیف‌های تومانی، `"usd"` برای مواردی که
     از اول به دلار هستند (امروز فقط انس طلا، ولی هر بار چک کن، فرض نکن)
   - `change_24h`: رشته‌ی تغییرات ۲۴ ساعته دقیقاً همان‌طور که نشان داده شده
     (مثلاً `"+0.94%"`) — بدون تغییر یا محاسبه‌ی مجدد
   - `source_url`: لینک «جزئیات» همان ردیف

3. **قالب‌بندی و رند کردن (این کار را خودت به‌جای اسکریپت انجام بده، طبق
   دقیقاً همین قوانین):**

   - اگر `raw_currency == "usd"`: تغییری نده.
     `price = raw_price`, `unit = "دلار"`.
     (مثال: انس طلا با raw_price=4111 → price=4111, unit="دلار")

   - اگر `raw_currency == "toman"` و `raw_price >= 1,000,000`:
     `price = round(raw_price / 1,000,000)`, `unit = "میلیون تومان"`.
     (مثال: گرم طلا raw_price=17,937,120 → 17,937,120/1,000,000 = 17.93712
     → رند به ۱۸ → price=18, unit="میلیون تومان")

   - اگر `raw_currency == "toman"` و `raw_price < 1,000,000`:
     `price = round(raw_price / 1,000)`, `unit = "هزار تومان"`.
     (مثال: دلار raw_price=181,800 → 181,800/1,000 = 181.8 → رند به ۱۸۲ →
     price=182, unit="هزار تومان")

   - **قانون رند کردن: نیم به بالا (round-half-up)، نه رند به زوجِ نزدیک‌تر.**
     یعنی دقیقاً روی مرز ۰.۵ همیشه به بالا رند کن، نه به نزدیک‌ترین عدد زوج.
     (مثال حیاتی: ربع سکه raw_price=54,500,000 → 54,500,000/1,000,000 = 54.5
     → چون دقیقاً روی نیم است، به بالا رند می‌شود → price=55، نه ۵۴.
     این نکته را با دقت رعایت کن، این‌جا رایج‌ترین جای اشتباه است.)

   - هیچ رقم اعشار در خروجی نهایی `price` نباشد (طبق درخواست کاربر: «بدون
     اعشار»). `price` همیشه باید یک عدد صحیح باشد.

4. **نمایش دو خروجی به کاربر:**

   الف) جدول فارسی راست‌به‌چپ با دقیقاً همین چهار ستون، به همان ترتیب ثابت
   موارد بالا:

   | نوع | قیمت | واحد قیمت | تغییرات اخیر |
   |---|---|---|---|
   | دلار | 182 | هزار تومان | +0.94% |
   | انس طلا | 4111 | دلار | +0.76% |
   | گرم طلا | 18 | میلیون تومان | +0.84% |
   | سکه امامی | 182 | میلیون تومان | +0.28% |
   | نیم سکه | 95 | میلیون تومان | +0.53% |
   | ربع سکه | 55 | میلیون تومان | +0.93% |

   ب) آبجکت JSON استاندارد و ثابت (مدل داده‌ی اصلی — کلیدها همیشه انگلیسی،
   `title_fa` عنوان فارسی است):

   ```json
   {
     "source": "https://baha24.com/",
     "fetched_at": "<ISO8601 زمان دریافت>",
     "items": [
       {
         "key": "usd",
         "title_fa": "دلار",
         "symbol": "USD",
         "raw_price": 181800,
         "raw_currency": "toman",
         "price": 182,
         "unit": "هزار تومان",
         "change_24h": "+0.94%",
         "source_url": "https://baha24.com/price/قیمت_دلار"
       }
       // ... به همین شکل برای بقیه‌ی پنج مورد
     ]
   }
   ```

   این ساختار JSON هرگز نباید بین اجراهای مختلف عوض شود — چون قرار است
   داشبورد بریفینگ صبحگاهی یا هر ابزار دیگری مستقیم روی آن حساب کند.

   کارهای میانی (استخراج خام، محاسبات) را نمایش نده، مگر کاربر بخواهد — فقط
   جدول و JSON نهایی را نشان بده.

## نکات

- اگر baha24.com در دسترس نبود یا یک ردیف پیدا نشد، صریحاً همان مورد را
  اعلام کن (به‌جای حدس زدن یا استفاده از عدد قدیمی).
- اگر کاربر خواست موردی اضافه/حذف شود یا واحد یک مورد خاص فرق کند، فقط برای
  همان درخواست انجامش بده، نه این‌که پیش‌فرض این فایل را خاموش تغییر بدهی.
